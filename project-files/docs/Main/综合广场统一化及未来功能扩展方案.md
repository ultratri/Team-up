# 综合广场（生态广场）统一化及未来功能扩展方案

## 1. 现状调研与问题分析

### 1.1 现有功能现状
- **项目广场 (`ProjectSquare.vue`)**：核心招募地，目前支持基础的分类和关键词搜索，但缺乏“智能匹配”和“新手保护”机制的视觉呈现。
- **导师广场 (`MentorPlaza.vue`)**：展示导师名片，主要用于导师的选择与评分。
- **比赛广场 (`CompetitionList.vue`)**：列出赛事信息，与项目组队的关联性较弱。
- **发现功能**：目前在 UI 上散落在各处，缺乏系统化的资源沉淀（如项目成果、面经分享）。

### 1.2 核心痛点
- **入口分散**：用户需要频繁切换页面来完成“找比赛、找导师、找队友”的流程。
- **资源浪费**：往届比赛的项目成果、面经、资料没有沉淀到广场，新用户“冷启动”难。
- **缺乏匹配度感知**：用户在广场中无法直观看到哪个项目或队友最适合自己。

---

## 2. “综合广场”统一化架构设计

建议将现有的零散广场统一升级为 **“生态综合广场 (Ecosystem Hub)”**，采用顶部 Tab 或左侧侧边栏进行模块化切换。

### 2.1 模块构成 (Tab 划分)
1. **项目大厅 (Project Hall)** - *原项目广场升级*
   - 增加“新手友好”、“急需前端”等标签。
   - 增加“匹配度分数”预览。
2. **组队/人才广场 (Talent Square)** - *由导师广场扩展升级*
   - **逻辑**：实现“成员找项目”与“项目招募成员”的双向奔赴。增加“人才墙”或“组队意向墙”，让活跃用户主动展示技能，被项目发起人“反向挖掘”。
   - **核心项**：用户技能标签、信誉分、新手标识、求带/带人意向。
3. **赛事中心 (Competition Center)** - *原比赛广场*
   - 展示比赛详情，并直接关联该比赛下正在招募的项目。
4. **资源/成果广场 (Asset/Showcase Square)** - *新增*
   - **逻辑**：对应项目完成后的归档。项目结束后，产出的开源代码、文档、经验贴集中展示。
   - **核心项**：项目成果预览、GitHub 链接、技术栈、团队心得、面经分享。
5. **动态/成长广场 (Moment Square)** - *基于轻社交逻辑*
   - **逻辑**：建立用户粘性，展示用户关注的项目动态、导师动态、勋章获得情况，记录个人/团队成长轨迹。

## 3. 未来建议新增的广场性质功能

### 3.1 组队实验室 (Teaming Lab) - 【智能组队广场】
- **功能描述**：系统基于用户的技能画像和兴趣，自动推荐 3-5 个技能互补的用户进入一个临时的“聊天室”或“兴趣小组”。
- **价值**：打破新用户不敢主动申请项目的僵局，通过系统撮合降低组队门槛。

### 3.2 任务/悬赏广场 (Task/Bounty Square) - 【轻量任务广场】
- **功能描述**：针对团队协作功能边界的延伸。项目不需要长期成员，只需要短期解决特定问题（如：帮画一个 Logo，帮写一个爬虫）。
- **核心项**：任务描述、截止日期、所需技能、报酬/积分。
- **价值**：适合时间碎片化用户，也是新用户展示技能、积累信誉分的“新手村”。

## 4. 业务闭环与技术落地建议

### 4.1 业务闭环设计
1. **发现**：用户在“资源广场”看到往届获奖项目 -> 产生参赛冲动。
2. **连接**：在“赛事中心”找到近期比赛 -> 在“人才森林”咨询导师或在“组队实验室”匹配队友。
3. **执行**：创建项目并完成。
4. **沉淀**：项目结束后，成果自动同步至“资源广场”，导师评价计入“人才森林”信誉分。

### 4.2 技术改进建议
- **统一搜索服务**：建立 Elasticsearch 或基础的全文索引，支持跨项目、跨比赛、跨人才的全局搜索。
- **标签系统标准化**：将前端、后端、算法等技能标签在所有广场中统一，支持点击标签进行关联过滤。
- **新手保护 UI**：在广场中对新用户（注册<30天）标记“新锐”徽章，并在匹配算法中给予权重倾斜。
