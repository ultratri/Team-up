# 导师功能文档

## 1. 引言
本文档详细描述了“导师”（Mentor）角色在平台上的功能定位、业务逻辑及操作流程。导师制度是平台解决新老用户公平性问题（冷启动问题）的核心机制之一，旨在鼓励资深用户（学长学姐、技术专家）带领新用户成长，形成良性的社区互助氛围。

## 2. 角色定义与资格
*   **角色定位**：拥有丰富项目经验、高信誉分的老用户，或者通过特定认证的领域专家。
*   **资格获取逻辑**：
    *   **自动触发**：系统检测到用户信誉分达到特定阈值（如 > 80分）且完成项目数达到一定数量（如 > 5个）时，自动提示邀请其成为导师。
    *   **主动申请**：用户可在个人中心发起“导师资格申请”，提交相关证明材料（如获奖证书、大厂实习证明）。
    *   **审核流程**：申请需经管理员审核通过后生效，获得“导师”身份标识。

## 3. 核心业务流程

### 3.1 建立师徒关系
*   **情景**：导师希望利用业余时间指导新人，获取平台奖励；新手希望获得专业指导。
*   **功能逻辑**：
    *   **导师展示**：在专门的“导师广场”或新用户的推荐页中展示导师卡片，突出显示导师擅长的领域、过往辅导人数及好评率。
    *   **双向选择**：
        *   **学员申请**：新用户可向导师发送指导申请，附带个人目标和当前困惑。
        *   **导师邀请**：导师可浏览“求指导”的新用户列表，主动发出邀请。
    *   **关系绑定**：双方确认后，系统记录师徒关系，状态为“进行中”。一个导师可同时辅导多名学员（有上限），一个学员同一时期只能有一名主导师。

### 3.2 指导与互动
*   **情景**：在项目进行过程中，学员遇到技术难题或方向困惑。
*   **功能逻辑**：
    *   **专属沟通通道**：建立师徒专属私信通道，支持文件传输、代码片段分享。
    *   **项目挂靠**：导师可以作为“顾问”角色被邀请进入学员的项目组，拥有查看项目进度、代码仓库和文档的权限，但通常不承担具体的开发任务（Task）。
    *   **定期回顾**：系统提示导师定期（如每两周）对学员的成长进行简单反馈。

### 3.3 关系结束与结算
*   **情景**：学员完成了既定目标（如完成了第一个项目，或度过了新手保护期）。
*   **功能逻辑**：
    *   **目标达成判定**：当学员成功完成首个项目或信誉分达到一定标准（如60分），系统自动判定辅导目标达成。
    *   **主动结束**：任何一方也可选择提前终止关系。
    *   **评价反馈**：关系结束时，学员需对导师的指导进行评价（评分+评语）。

## 4. 激励与权益体系
为了维持导师的积极性，平台设计了多维度的激励机制。

### 4.1 积分奖励
*   **逻辑**：
    *   **基础奖励**：每成功辅导一名学员（达成目标），获得固定信誉积分奖励（如+50分）。
    *   **绩效奖励**：若学员在辅导期间获得高评价或项目获得奖项，导师获得额外积分加成。

### 4.2 荣誉体系
*   **逻辑**：
    *   **导师徽章**：根据累计辅导人数和好评率，颁发不同等级的导师徽章（如“金牌导师”、“引路人”）。
    *   **徽章展示**：徽章将在个人主页、评论区等所有公开场合显著展示，满足用户的荣誉感。

### 4.3 优先推荐权
*   **逻辑**：
    *   拥有优秀导师记录的用户，在自己发布项目招募成员时，系统会给予更高的曝光权重。
    *   在“智能组队推荐”算法中，导师发起的项目会优先推荐给优质用户。

## 5. 总结
导师功能模块不仅是新用户的“助推器”，也是老用户的“成就感来源”。通过**“师徒匹配 -> 过程指导 -> 成果结算 -> 激励反馈”**的闭环逻辑，有效地将平台内的存量资源（老用户经验）转化为增量价值（新用户成长），从而构建可持续发展的社区生态。
