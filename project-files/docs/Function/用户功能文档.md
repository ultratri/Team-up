# 用户功能文档

## 1. 引言
本文档详细描述了普通用户（包括项目创建者、团队成员、求职者等）在平台上的功能和业务逻辑。旨在通过清晰的情景描述，阐明用户如何使用平台完成组队、协作和社交目标。

## 2. 核心业务流程

### 2.1 项目与组队核心流程
用户在平台上的核心活动围绕“项目”展开，项目是组队的最小单元。

#### 2.1.1 创建项目（发起组队）
*   **情景**：用户希望发起一个新项目，可能是为了参加某个比赛，也可能是为了做一个课外项目。
*   **功能逻辑**：
    *   **项目创建向导**：用户填写项目名称、描述、所需技能（支持标签选择）、最大成员数。
    *   **关联比赛（可选）**：如果项目是为了参赛，用户可以从平台现有的比赛列表中选择关联。
    *   **组队模式选择**：
        *   **创建新团队**：默认模式。招募完成后系统将自动生成一个新团队。
        *   **使用已有团队**：作为长期团队的队长，可以选择以现有团队身份发起新项目，延续团队历史。
    *   **难度标记**：用户可以标记项目为“新手友好”，吸引新用户加入。

#### 2.1.2 寻找与加入项目
*   **情景**：用户（特别是大一、大二学生）希望寻找项目锻炼能力。
*   **功能逻辑**：
    *   **智能推荐**：系统根据用户的技能、兴趣、可用时间以及信誉分，推荐最匹配的项目。
    *   **多维筛选**：用户可按技能标签（如Vue.js, Python）、比赛类型、项目状态进行筛选。
    *   **申请加入**：用户查看项目详情（含匹配度评分），提交加入申请，可附带简短的自我介绍或作品集链接。

#### 2.1.3 审核与组队完成
*   **情景**：项目创建者收到了多个申请，需要挑选合适的队友。
*   **功能逻辑**：
    *   **申请管理**：创建者查看申请人列表，列表中展示匹配度详情（技能匹配、时间匹配、信誉分）。
    *   **处理申请**：创建者批准或拒绝申请。
    *   **自动成团**：当确认成员后，系统根据项目设置自动生成“团队”实体，所有成员进入团队空间，项目状态变更为“进行中”。

#### 2.1.4 项目结项与团队演化
*   **情景**：项目开发结束，或者比赛结束。
*   **功能逻辑**：
    *   **结项操作**：队长将项目状态变更为“已完成”。
    *   **团队去留决策**：
        *   **解散团队**：针对临时组队，成员关系解除，团队归档。
        *   **保留团队**：针对长期合作意向，团队保留，沉淀项目经验，未来可直接以该团队身份接新项目。
    *   **互评机制**：成员之间进行互评，评价结果影响个人信誉分。

## 3. 团队协作功能
一旦组队成功，团队成员进入专属的协作空间。

### 3.1 任务管理
*   **功能**：提供轻量级的看板视图（To Do, In Progress, Done）。
*   **逻辑**：
    *   成员可以创建任务，指派给特定人员，设置截止日期和优先级。
    *   支持任务评论和附件上传，方便针对具体任务讨论。

### 3.2 实时沟通
*   **功能**：内置团队群聊和私聊功能。
*   **逻辑**：
    *   团队创建时自动生成群组。
    *   支持文本、表情、文件分享、@提醒功能。
    *   消息状态支持已读/未读显示，确保沟通效率。

### 3.3 文件与资源管理
*   **功能**：团队共享的文件存储空间。
*   **逻辑**：
    *   支持文件上传、下载、文件夹分类。
    *   提供简单的版本记录，防止文件误覆盖。

### 3.4 开发集成
*   **功能**：集成代码托管平台信息。
*   **逻辑**：
    *   队长可在设置中关联GitHub/Gitee仓库地址。
    *   系统在协作页展示最新的Commit记录和Issue状态，方便非技术成员了解进度，无需离开平台。

## 4. 个人成长与信誉体系

### 4.1 新手保护与成长
*   **情景**：新注册用户缺乏历史记录，难以组队。
*   **逻辑**：
    *   **新手保护期**：注册30天内享受信誉分加成，便于被推荐。
    *   **新手任务**：完成完善资料、技能认证等任务可获得初始积分和徽章。
    *   **技能认证**：用户可上传证书、GitHub项目链接等材料，通过审核后获得“已认证”标识，大幅提升匹配权重。

### 4.2 个人资料与展示
*   **功能**：展示用户的全方位能力画像。
*   **逻辑**：
    *   **六维能力图**：展示技能、经验、信誉等维度的雷达图。
    *   **标签系统**：展示技能标签（硬技能）、性格标签（软技能）和兴趣标签。
    *   **动态时间轴**：展示用户参与过的项目、获得的成就和徽章。

## 5. 社交互动
*   **情景**：用户希望拓展人脉，关注优秀的开发者。
*   **逻辑**：
    *   **关注机制**：单向关注感兴趣的用户，及时获取其新项目动态。
    *   **项目收藏**：收藏感兴趣但暂时无法参加的项目。
    *   **私信**：在组队前或社交场景下，进行一对一沟通。

## 6. 总结
用户端功能设计的核心是**“降低门槛，促进匹配，轻量协作”**。通过结构化的项目流程引导用户完成从“找人”到“做事”的全过程，同时利用信誉体系和社交功能解决信任问题。
